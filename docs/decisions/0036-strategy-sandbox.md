# 0036 — Strategy sandbox (RES-5)
- **Pipeline:** static AST allowlist → ruff lint → child process → lookahead truncation test + smoke backtest on seeded synthetic data → draft + JSON report in `data/drafts/`. Code that fails the static check is never executed.
- **Two independent layers:**
  1. **Static:** imports are limited to pure modules and the Strategy API. It forbids `eval`/`exec`/`compile`/`open`/`getattr`/`__import__`, dunder access (except `super().__init__`), `global`, async code, and top-level statements other than definitions.
  2. **Runtime:** `python -I -m helm.research.sandbox.runner`. The child gets an empty environment (no credentials), a temp working directory, `RLIMIT_CPU` and a memory limit (where the OS enforces it), and a wall-clock timeout. A `sys.addaudithook` installed before the draft loads blocks file writes, sockets, subprocesses, `os.system`/exec/fork, file deletes and renames, `shutil`, `ctypes`, env changes and non-memory SQLite. Every blocked attempt is recorded. The engine deliberately swallows strategy exceptions, so the record, not the exception, decides the verdict.
- **Never deploys:** drafts live outside `helm.strategy`, and `load_strategy` only loads `helm.strategy.*`. Backtest, validate, promote and live all go through that loader, so a draft must be moved into the codebase by a person before any of it applies.
- **Limits:** this is defense in depth for research code you or an LLM wrote, not a hostile-code jail. On macOS, `RLIMIT_AS` isn't enforced (the timeout and CPU limit still apply). Use the Docker `research` profile (no network) for extra isolation.
